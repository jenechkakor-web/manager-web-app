# Реестр выплат — локальная версия

Запуск: `npm start`, затем http://127.0.0.1:4173/payouts.html.
Используются существующие локальные пользователи и сделки из `.data/`.

## Расчёт

- Выручка — полная сумма всех сделок менеджера, отбор по дате договора.
- Автоматический бонус — только «Оплачен: Да», без недоплаты и «Закрывашки: Отправлены».
- «Не нужно» не даёт бонуса. Процент берётся из сделки; «оклад» даёт ноль, «от прибыли» — вручную указанную в сделке сумму.
- Дата автоматического начисления — момент выполнения обоих условий (`bonusQualifiedAt`, устанавливается сервером). День показывается по Москве. Изменение названия или другого поля сохраняет эту дату. Отмена условий убирает начисление; повторное выполнение ставит новую дату. Размер автоматических начислений рассчитывается по текущим данным сделок.
- Для исторических сделок без этой даты бонус учитывается в общем остатке и явно помечается как недатированный. В месячные начисления и остатки выбранного периода он не входит. Даты из `updatedAt` не используются: изменение карточки не доказывает дату полной оплаты и отправки документов.
- Ручные начисления и выплаты датируются сервером по Москве. Выплата может превышать начисления: отрицательный остаток означает аванс.
- Главный остаток всегда за всё время по выбранному менеджеру; отдельно показываются начисления, выплаты и движение за период, входящий и исходящий остатки.
- Таблица показывает закрытые сделки с положительным начисленным бонусом, а также ручные начисления и выплаты. Столбцы: дата транзакции, номер, название, контрагент, сумма сделки, начисленный бонус, выплачено и основание; администратору также доступен менеджер. Дата транзакции сделки — дата начисления, ручной операции — дата её записи. Отсутствующая историческая дата явно отмечается и не подменяется. Названия ручных операций показываются в столбце названия. Выплаты относятся к менеджеру, а не к отдельной сделке, и показываются отдельными строками операций. Свод продолжает учитывать все операции.
- Таблица поддерживает сортировку по заголовкам (суммы сортируются как числа), перенос столбца за маркер слева, изменение ширины за правую границу и автоподбор двойным кликом по ней. Настройки сохраняются локально в браузере отдельно для каждого пользователя; без выбранной сортировки строки идут в исходном порядке по дате. С клавиатуры: Enter на границе — автоподбор, стрелки — ширина; Alt + стрелки на маркере — порядок.

## Данные и доступ

Новый журнал `.data/bonus-ledger.json` хранит сумму в копейках, тип, менеджера, причину, дату и автора. Каждый POST сериализован; повторная отправка того же идентификатора не создаёт дубликат. Предыдущее состояние сохраняется в `.data/payout-backups/`; запись нового журнала выполняется через временный файл и переименование. Ошибка чтения или резервирования прерывает сохранение.

GET `/api/payouts` ограничивает данные по ID авторизованного пользователя. Только администратор может добавлять операции. Клиентские параметры даты и владельца не могут повысить права. Сервер не изменяет договоры при сохранении выплаты или ручного начисления.

## Проверки и перенос

`node --test tests/payouts.test.cjs` — расчёты, даты, права, валидация, параллельные операции, идемпотентность и сохранность договоров.

`node tests/payouts-ui.cjs <путь к модулю playwright> <путь к браузеру>` — формы администратора, личный кабинет менеджера, фильтры, размеры экрана. Проверки создают изолированные каталоги `.data/payout-test-*` и `.data/payout-ui-*`; основная локальная база не подменяется.

PHP/MySQL-реализация: `api/payouts.php`. Журнал `manager_bonus_ledger` хранит только новые операции живого сайта; уникальный request ID исключает повторы. Даты начисления хранятся отдельно в `manager_bonus_qualification`, изменения даты и сделки выполняются в одной транзакции. Существующие договоры не мигрируют и не заменяются локальными данными.

Текущий PHP хостинга — 5.6.40. Проверки запускаются на PHP 5.6 и 8.1 с MySQL 5.7. Не использовать новый синтаксис PHP без проверки на текущем хостинге.

Перед созданием новых таблиц автоматически создаются проверенные по количеству строк копии существующих таблиц (`*_paybak_*`). Список копий находится в `manager_payout_migrations.backup_manifest`. Миграция защищена блокировкой и выполняется один раз; при ошибке создание новой схемы прекращается. Старые даты не выдумываются. Файлы сайта до переноса сохраняются в закрытом артефакте `manager-live-before-<run-id>` (30 дней); данные БД хранятся только на хостинге. При сбое публикации код восстанавливается из копии, новые таблицы не удаляются, выплаты и договоры не откатываются.

Публикация разрешена только после проверок расчётов, PHP/MySQL-миграции и HTTP API на отдельной тестовой базе. `tests/payouts-php.php` и `tests/payouts-php-http.cjs` проверяют резервирование, права, идемпотентность, даты и сохранность договоров. `.data/`, тестовые операции, `tests/` и `templates/contracts-registry.json` исключены из загрузки на хостинг.
